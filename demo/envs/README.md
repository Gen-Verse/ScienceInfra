# envs/ — level 1 of the three-level layout (env / category / task)

One directory per packaged repo. The env level holds everything that is
**heavy, shared, and per-repo**; the task level is **light, per-instance,
pure data**. This is the SWE-smith-shaped split (one environment per repo,
tasks as data applied to it), kept compatible with harbor's native unit —
the self-contained task directory — through a compiler.

    envs/<repo>/                  LEVEL 1 — one RL env per packaged repo
      env/                          the apparatus:
        cases/                      simulation configurations, one per graded
                                    scenario ("run a case": grid, tmax,
                                    physics switches — episode definitions)
        validation/                 per-case acceptance: validate.py (the
                                    comparator actually run by the verifier)
                                    + rubric.json (tolerances and the
                                    measured evidence behind them)
        scoring/                    validation verdict -> reward: grade.py
                                    (the ladder), test.sh, make_timing.py
        upstream-patches/           the small patches applied to the pinned
                                    upstream at build time (source is never
                                    vendored; clone + patch reproduces it)
      tasks.jsonl                 THE CANONICAL TASK ROWS — one JSON object
                                  per generated task: name, canary, graded
                                  checks, symptom text, the defect (break +
                                  fix transforms), and the full funnel
                                  verdict. A row fully determines its
                                  compiled task dir.
      tasks/<category>/<name>/    LEVEL 2 (taxonomy category) and LEVEL 3
                                  (concrete task): COMPILED harbor task dirs
                                  — the format `harbor run -p` loads
                                  natively; each category dir is a harbor
                                  dataset dir. Generated by
                                  utils/adapters/to_harbor.py; regenerable
                                  and byte-stable; never hand-edit one.

Naming note: compiled task dirs keep the source benchmark's wire format —
cases/ is vendored in as `decks/`, validation/ as `checks/`,
upstream-patches/ as `patches/`, and the in-container paths stay
`/app/decks`, `/app/checks`. That layer is a generated interface (donor-task
and ScienceAccelBench compatible), not something people read; the
scientist-facing names live here at the env level.

## Flows

```bash
# canonical -> harbor form (all rows, or a glob subset)
python3 utils/adapters/to_harbor.py        # tasks.jsonl -> envs/laps/tasks/<category>/
python3 utils/adapters/to_harbor.py --only 'laps-repair-norm-*'

# run with harbor's native dataset loading (a category dir is a dataset dir)
harbor run -p envs/laps/tasks/repair -i 'laps-repair-coef-*' -a <agent>
harbor run -p envs/laps/tasks/repair/laps-repair-coef-2d-rktmod-l17k1 -a oracle

# rows are (re)emitted from funnel outputs by the factory
python3 utils/authoring/repair/package.py --all --candidates ... --verdicts ...
```

## Rules

- **Never edit a compiled dir under tasks/** — edit the row (or the
  templates in utils/adapters/to_harbor.py) and recompile; gate_pack + the
  byte-identity regression treat compiled dirs as pure outputs.
- **The answer never enters agent-visible material.** Rows carry the fix;
  the compiler routes it exclusively into env-Dockerfile prep stages,
  tests/, and solution/. gate_pack's leak scan (self-tested with a planted
  leak) enforces this.
- **Adding a repo** = new `envs/<repo>/` + its factory under utils/authoring/ +
  rows; the task level and adapters are repo-agnostic by construction.

## Why not "one global image"

Per-repo images are the sweet spot (SWE-smith: one image per repo, "1000
tasks = 1GB, not 1TB"; SWE-bench's per-instance images cost 240GiB).
Cross-repo toolchains conflict, so a single global image bloats and drifts;
per-task images cost storage and build time. Docker layer content-addressing
already dedupes everything shared across our compiled tasks (~5MB marginal
per task); `[environment] docker_image` in task.toml is the harbor-native
hook for pointing tasks at prebuilt registry images when a fleet needs it.
